# Задача змагання: інтерпретатор машини Тьюрінга

## Задача

Написати інтерпретатор машини Тьюрінга.

Наскільки мала реалізація інтерпретатора машини Тьюрінга може бути, якби вона була написана на асемблері? Це змагання дозволить нам визначити справжніх майстрів низькорівневого кодування.

Будь-ласка, дотримуйтесь наступних вимог.

---

## Формат вхідного файлу (.tm)

Вхідний файл — текстовий, містить опис машини Тьюрінга та вхідний рядок стрічки.

### Структура файлу

```
; Коментар (рядки, що починаються з ;)
; Порожні рядки ігноруються

; Заголовок (перший непорожній некоментарний рядок):
start_state halt_state

; Правила переходу (кожний рядок):
current_state read_symbol new_state write_symbol direction

; Вхідний рядок стрічки (після порожнього рядка з маркером ---):
---
вхідний рядок тут
```

### Токени

- **Стани** (`start_state`, `halt_state`, `current_state`, `new_state`): рядки без пробілів, 1–8 символів. Можуть містити літери, цифри, дефіс, підкреслення (окрім одиночного `_`). Приклади: `q0`, `carry`, `done`, `s1`.
- **Символи** (`read_symbol`, `write_symbol`): один друкований ASCII-символ (коди 33–126), або `_` для позначення порожньої комірки (blank). Символ `_` **завжди** означає blank і не може використовуватись як символ даних.
- **Напрямок** (`direction`): `L` (ліворуч), `R` (праворуч), `N` (залишитись на місці).
- Токени розділяються пробілами або табуляцією. Кожне правило переходу — на окремому рядку.

### Вхідний рядок (стрічка)

Після рядка `---` йде рівно один рядок — початковий вміст стрічки. Якщо рядок порожній або `---` відсутній, стрічка ініціалізується повністю порожньою (blank).

Вхідний рядок може містити будь-які друковані ASCII-символи (коди 33–126) та пробіли (код 32). Символ `_` у вхідному рядку — допустимий звичайний символ (код 95), а **не** blank.

> **Примітка.** `_` у правилах переходу означає blank (порожня комірка, внутрішнє значення 0). `_` у вхідному рядку — це звичайний ASCII-символ 95 на стрічці. Це різні речі.

### Приклад файлу

```
; Двійковий NOT: заміна 0 на 1 та 1 на 0
scan done

scan 0 scan 1 R
scan 1 scan 0 R
scan _ done _ N
---
10110
```

Результат: `01001`

## Семантика виконання

### Стрічка (tape)

- Стрічка складається з комірок, кожна зберігає один байт (0–255).
- **Порожня комірка** (blank) має значення **0**.
- Стрічка концептуально нескінченна в обох напрямках. Реалізація повинна підтримувати щонайменше **10 000 комірок** в кожному напрямку від початкової позиції (всього щонайменше 20 001 комірка).
- Перед початком виконання всі комірки ініціалізовані значенням 0 (blank).

### Завантаження вхідного рядка

- Кожен символ вхідного рядка записується в комірку стрічки, починаючи з позиції 0 (один символ = один байт = його ASCII-код).
- Головка (head) встановлюється на позицію 0.

### Крок виконання

1. Прочитати значення комірки під головкою.
2. Знайти правило переходу `(current_state, read_symbol)`.
3. Якщо правило знайдено:
   - Записати `write_symbol` у поточну комірку.
   - Перемістити головку: `L` = позиція − 1, `R` = позиція + 1, `N` = без руху.
   - Перейти до `new_state`.
4. Якщо правило **не знайдено** і поточний стан **не є** `halt_state` — це помилка. Гарантується, що у всіх тестах такої ситуації не виникне.

### Зупинка

Машина зупиняється, коли поточний стан стає рівним `halt_state`.

> **Примітка.** Зупинка відбувається **перед** спробою виконати перехід. Тобто якщо машина перейшла в `halt_state` — вона зупиняється негайно, без пошуку чергового правила.

### Обмеження кроків

Гарантується, що всі тестові програми завершуються. Якщо програма працює **довше 60 секунд** в DOSBox-X на тестовому комп'ютері, тест вважається непройденим.

## Вивід результату

Після зупинки машини виводиться вміст стрічки у stdout.

**Що виводити:** всі комірки від позиції **першої непорожньої** (найлівішої з ненульовим значенням) до позиції **останньої непорожньої** (найправішої з ненульовим значенням), включно. Порожні комірки (blank, значення 0) всередині цього діапазону виводяться як пробіл (код 32).

**Якщо всі комірки порожні** — вивід порожній (0 байтів).

Вивід не повинен містити символу нового рядка в кінці. Stdout може бути перенаправленим.

## Обмеження

| Параметр | Значення |
|----------|----------|
| Максимальний розмір файлу .tm | 32 000 байтів |
| Максимальна довжина вхідного рядка | 10 000 символів |
| Мінімальний розмір стрічки | 10 000 комірок в кожен бік від позиції 0 |
| Максимальний розмір вхідного рядка + дописаних символів | 32 768 комірок |
| Максимальна кількість станів | 256 |
| Максимальна довжина імені стану | 8 символів |
| Максимальний час виконання | 60 секунд в DOSBox-X |
| Символи вхідного рядка | друковані ASCII (32–126) |
| Символи в правилах | друковані ASCII (33–126) та `_` для blank |

## Запуск програми

```
F:\> tm program.tm
```

- `tm` (або `tm.com`) — інтерпретатор.
- `program.tm` — файл з описом машини Тьюрінга та вхідним рядком.
- Вхідний рядок читається **з файлу .tm** (після маркера `---`), **не** зі stdin.
- Результат виводиться у **stdout**. Stdout може бути перенаправленим:

```
F:\> tm program.tm >result.txt
```

Гарантується, що файл існує, доступний і містить правильну програму. Перевірок коректності робити не потрібно.

---

## Спеціальні випадки та гарантії

- **Коректність програми.** Усі тестові файли .tm містять коректні програми: збалансовані правила, всі досяжні стани мають визначені переходи (або є halt_state). Перевірки коректності не потрібні.
- **Гарантія зупинки.** Усі тестові програми завершуються за скінченну кількість кроків.
- **Дублікати правил.** Гарантується, що у вхідному файлі немає дублікатів правил (однакова пара `state + read_symbol`).
- **Порожній вхідний рядок.** Якщо після `---` немає рядка або `---` відсутній, стрічка повністю порожня (blank). Машина починає виконання з blank під головкою.
- **Ідентичні start і halt стани.** Якщо `start_state == halt_state`, машина зупиняється негайно (без виконання жодного кроку). Вивід = вхідний рядок як є.
- **NUL (ASCII 0).** NUL не з'являється у вхідних файлах. Вивід не повинен містити NUL (порожні комірки всередині діапазону виводу замінюються пробілом).
- **CR/LF.** Файли .tm можуть мати будь-які закінчення рядків (CR+LF або LF). Парсер має обробляти обидва варіанти. Вивід не повинен містити CR або LF.

## Компіляція та тестування

Найпростіший спосіб — запустити `TESTALL.BAT` зі спільного репозиторію. Він скомпілює програму та запустить **всі** тести:

```
F:\> TESTALL
```

Цей скрипт:
1. Компілює `cmp.asm` (утиліта порівняння)
2. Компілює `tm.asm` з `F:\`
3. Запускає `TM.COM` на кожному тесті з `F:\tests\`
4. Порівнює вивід з еталонним `.ok` файлом
5. Показує `[PASS]` або `[FAIL]` для кожного тесту

Якщо ви хочете запустити один тест вручну:

```
F:\> tasm /zi tm.asm
F:\> tlink /t /v tm.obj
F:\> tm.com F:\tests\01.tm
```

Результат: `TM.COM` — саме його розмір є результатом у змаганні.

Для відлагодження у Turbo Debugger:

```
F:\> td tm.com F:\tests\01.tm
```

## Тести

Кожен тест — це файл `.tm` (програма + вхідний рядок) та файл `.ok` (очікуваний вивід). Обидва знаходяться в `tests/`.

Вивід програми порівнюється з `.ok` побайтово. Тест пройдено, якщо файли ідентичні.

### Базові (00–06, 01a–06a)

Перевіряють основну функціональність інтерпретатора. Проходження базового набору — поріг для збереження автоматичних балів.

### Крайні випадки (e01–e15)

Тести на граничні ситуації парсера та виконавця.

| Тест | Опис |
|------|------|
| e01 | **Табуляція як роздільник.** Токени розділені табами замість пробілів (специфікація: «пробіли або табуляція»). |
| e02 | **Коментарі між правилами.** Рядки `;` та порожні рядки всередині списку правил — парсер має їх пропускати. |
| e03 | **Імена станів з дефісами та підкресленнями.** Перевірка, що парсер приймає `go-r`, `go_r` тощо. |
| e04 | **Порожня стрічка.** Маркер `---` присутній, але після нього порожній рядок. Машина починає на blank. |
| e05 | **`_` у вхідному рядку = ASCII 95, а не blank.** Символ `_` на вході — звичайний символ, не порожня комірка. |
| e06 | **Пробіли у вхідному рядку.** Пробіли (ASCII 32) у вхідних даних мають зберігатися як є. |
| e07 | **Внутрішні blank у виводі стають пробілами.** Якщо між двома непорожніми комірками є blank (0), він виводиться як пробіл (32). |
| e08 | **Усі комірки порожні — вивід 0 байтів.** Машина стирає весь вхід, вивід має бути порожнім. |
| e09 | **Зупинка на першому переході.** Перше правило одразу переводить у halt-стан. |
| e10 | **Вивід значно більший за вхід.** З одного вхідного символу генерується 20 символів виводу. |
| e11 | **Спецсимволи ASCII: `!`, `~`, `@`, `#`.** Перевірка, що символи з кодами 33–126 працюють у правилах та на стрічці. |
| e12 | **Змішані табуляція та пробіли.** В одному файлі одні правила розділені пробілами, інші — табами. |
| e13 | **Імена станів довжиною 8 символів.** Максимальна дозволена довжина імені стану за специфікацією. |
| e14 | **Запис `_` створює blank.** Правило пише `_` — це blank (0), а не ASCII 95. Blank всередині виводу стає пробілом. |
| e15 | **Закінчення рядків CR+LF.** Файл використовує Windows-style закінчення рядків (CR+LF). Парсер має обробляти обидва варіанти. |

### Стрес-тести (s01–s05)

Тести на продуктивність та межі специфікації.

| Тест | Опис |
|------|------|
| s01 | **Бульбашкове сортування (~314K кроків).** Сортує рядок із 500 символів алгоритмом bubble sort. Перевіряє тривале виконання. |
| s02 | **Максимальний вхід (9999 символів).** Простий прохід по рядку з 9999 символів. Перевіряє буфер стрічки біля межі 10 000. |
| s03 | **Широка стрічка (2001 комірка, ~8K кроків).** Машина робить 4 проходи туди-назад по 2001 комірці. Перевіряє широкий діапазон стрічки. |
| s04 | **60 станів.** Кожен символ проходить ланцюжок із 60 станів. Перевіряє пошук у таблиці переходів. |
| s05 | **256 станів (межа специфікації).** Ланцюжок із 255 проміжних станів — максимум за специфікацією. Перевіряє розмір таблиці станів. |

## Поради для I/O на асемблері

Для роботи з файлами та I/O вам знадобляться виклики INT 21h:

| Функція | Призначення |
|---------|-------------|
| `AH=3Dh` | Відкрити файл (Open file handle) |
| `AH=3Fh` | Читати з файлу або пристрою (Read file/device) |
| `AH=40h` | Записати у файл або пристрій (Write file/device) |
| `AH=3Eh` | Закрити файл (Close file handle) |
| `AH=4Ch` | Завершити програму (Terminate with return code) |

Ім'я файлу передається як аргумент командного рядка. Для доступу до нього у COM-програмі:
- `DS:[80h]` — довжина командного рядка
- `DS:[81h]` і далі — текст командного рядка (починається з пробілу)

> **Підказка.** Рядок у PSP завершується символом CR (0Dh). Для `AH=3Dh` потрібен рядок, завершений NUL (0). Замініть CR на 0 перед відкриттям файлу, або скопіюйте ім'я файлу в окремий буфер з NUL-терміналом.
